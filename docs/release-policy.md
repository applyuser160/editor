# Oxide Editor リリースポリシー

この文書は、Git タグから生成する配布物、署名、更新、ロールバックの運用基準を定めます。**秘密鍵、証明書、パスワード、ノータリゼーション用資格情報は、リポジトリ、Issue、プルリクエスト、リリースノート、ログに保存してはいけません。**

## 配布対象と検証

| OS              | 配布形式                    | CIで行う検証                                                                                      | 署名・配布に必要な管理情報                                                                                           |
| --------------- | --------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Linux x86_64    | Debian パッケージ、AppImage | クリーンな Ubuntu runner 上で Debian パッケージのインストール、起動、アンインストールを検証する。 | Tauri アップデーター署名鍵。将来のリポジトリ署名鍵。                                                                 |
| Windows x86_64  | MSI、NSIS                   | Windows runner で成果物と SHA-256 を生成する。                                                    | コード署名証明書とパスワードを GitHub Actions Secrets で管理する。                                                   |
| macOS Universal | `.app`、DMG                 | macOS runner で成果物と SHA-256 を生成する。                                                      | Apple Developer 証明書、App Store Connect API キー、ノータリゼーション資格情報を GitHub Actions Secrets で管理する。 |

CI で生成する SHA-256 チェックサムは GitHub Release の添付ファイルとして公開します。利用者はダウンロード前後でチェックサムを照合できます。

## タグリリース

タグは `vMAJOR.MINOR.PATCH` 形式とします。`v*` タグへの push により、OS 別ビルド、Rust 単体テスト、バンドル生成、Linux Debian パッケージのクリーン環境テスト、SHA-256 生成、ドラフトリリース作成を実行します。

| 段階          | 実施内容                                                                                           | 失敗時の扱い                               |
| ------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 1. 品質確認   | 依存関係の復元、フロントエンドビルド、Rust テストを実行する。                                      | リリースを作成しない。                     |
| 2. 署名準備   | CI に注入された署名鍵が存在することを確認する。                                                    | ジョブを失敗させ、鍵の内容は出力しない。   |
| 3. OS別ビルド | Linux、Windows、macOS のバンドルを生成し、成果物を収集する。                                       | いずれかの対象が失敗した場合は公開しない。 |
| 4. Linux検証  | Debian パッケージをクリーン runner にインストールし、仮想表示で起動後、アンインストールする。      | 公開しない。                               |
| 5. 公開       | すべての成果物とチェックサムをドラフト GitHub Release へ添付し、自動生成リリースノートを確認する。 | ドラフトを公開しない。                     |

## 必須シークレット

次の値は GitHub Actions Secrets または organization-level secrets でのみ設定します。ワークフローは値の存在だけを確認し、値を表示しません。

| Secret                                                 | 用途                                                  |
| ------------------------------------------------------ | ----------------------------------------------------- |
| `TAURI_SIGNING_PRIVATE_KEY`                            | 更新メタデータ・配布物の Tauri 署名に使用する秘密鍵。 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`                   | 上記秘密鍵を暗号化した場合のパスワード。              |
| `APPLE_CERTIFICATE` / `APPLE_CERTIFICATE_PASSWORD`     | macOS アプリ署名用の証明書とパスワード。              |
| `APPLE_SIGNING_IDENTITY`                               | macOS コード署名 ID。                                 |
| `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID`        | macOS ノータリゼーションに必要な資格情報。            |
| `WINDOWS_CERTIFICATE` / `WINDOWS_CERTIFICATE_PASSWORD` | Windows コード署名に必要な証明書とパスワード。        |

> リポジトリへ公開してよいのは Tauri アップデーターの**公開鍵**だけです。秘密鍵は生成元の安全なストレージと CI のシークレットストアに限定し、漏えい時は直ちに失効・ローテーションします。

## 更新とロールバック

自動更新を有効化する前に、署名済み更新メタデータを HTTPS で配信する運用先、公開鍵、サポート期間、更新失敗時の回復手順を決定します。更新エンドポイント、公開鍵、または署名鍵を変更する場合は、旧版からの更新とロールバックの両方をステージング環境で検証します。

不具合のある公開済みリリースは削除・上書きせず、GitHub Release 上で非推奨または取り消しの状態を明記します。修正版には新しいバージョンタグを付与し、変更内容、既知の制約、影響する OS、依存関係の変更をリリースノートに記載します。署名鍵の漏えいが疑われる場合は、配布を停止し、鍵をローテーションしてから新しい公開鍵で署名した更新を発行します。
