# Rust製軽量IDE 要件定義書（SRS簡易版）

> ISO/IEC/IEEE 29148 をベースにした軽量版要件定義書です。  
> VS Code の代替となる、Rust 製のメモリ効率とパフォーマンスに特化した次世代 IDE の機能・非機能要件を定義します。

## 1. 目的・スコープ

### 1.1 目的

現代のコードエディター（特に Electron ベースの IDE）は高機能である反面、メモリ消費量の肥大化や起動遅延、巨大ファイル編集時のレスポンス低下という課題を抱えています。  
本プロジェクトは、Rust のメモリ安全性とゼロコスト抽象化、GPU 加速レンダリング、Rope データ構造を活用し、アイドル時メモリ消費 50MB 未満・起動時間 100ms 未満・ギガバイト級ファイルでも遅延なく編集できる VS Code 代替 IDE を開発・提供することを目的とします。

### 1.2 スコープ

**スコープ内:**
- テキストエディターコア（Rope バッファ、マルチカーソル、Undo/Redo）
- Tree-sitter および Language Server Protocol (LSP) によるシンタックス/セマンティックハイライト、コード補完、定義ジャンプ、エラー診断
- ファイルツリー / ディレクトリ構造の可視化とファイル操作
- Git GUI 操作（変更差分表示、ステージング/アンステージング、コミット、ブランチ操作）
- 統合ターミナル実行機能（PTY 連携、VT100/XTerm シーケンス処理）
- 拡張機能システム（WASM による安全なプラグイン実行、テーマ/キーバインドカスタマイズ）
- 高速検索機能（ファイル内検索・置換、ripgrep 連携によるプロジェクト全体検索、ファイル名ファジー検索）
- Markdown のリアルタイム・プレビューレンダリング機能（スプリットビュー同期）

**スコープ外:**
- クラウド同期・リモート開発サーバー専用ホスティング（初期フェーズでは対象外）
- Electron / Web ブラウザ上での動作（ネイティブバイナリのみを対象）

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| Rope | 巨大な文字列を木構造のノード列として分割管理し、O(log N) での挿入・削除を可能にするデータ構造 |
| Tree-sitter | 増分構文解析（Incremental Parsing）をサポートする高速なパーサージェネレーター |
| LSP | Language Server Protocol。エディターと言語解析サーバー間の標準通信規約 (JSON-RPC 2.0) |
| PTY | Pseudoterminal（仮想端末）。ターミナルプロセスの入出力を制御するインターフェース |
| WASM | WebAssembly。サンドボックス環境下で高速に動作するバイナリ命令フォーマット |
| Semantic Tokens | 言語サーバーが AST 解析結果に基づいて提供する詳細なトークン情報（型、変数、関数等の区別） |

## 3. 全体要件

### 3.1 ユーザーニーズ

- 多数のプロジェクトや巨大なリポジトリを開いても、OSのメモリを圧迫せず軽快に動作すること。
- キーボードショートカットや UI 操作が VS Code と同等に直感的であること。
- コード補完やエラー診断が型定義に沿って遅延なく表示されること。
- 外部ツール（Git, ターミナル, 検索）をエディター内部でシームレスに完結できること。

### 3.2 前提条件・制約

**前提条件:**
- 対象 OS: Windows 10/11 (x86_64), macOS 12+ (Apple Silicon / Intel), Linux (x86_64, Wayland/X11)
- Rust ツールチェーン (1.80 以上) によるクロスプラットフォームビルド

**制約:**
- UI レンダリングには Webview/Electron を使用せず、Rust ネイティブの GPU レンダリングエンジンを採用する。
- プラグイン実行エンジンはメモリ分離とクラッシュ耐性を保証するため、WASM ランタイムを使用する。

## 4. 機能要件

### 4.1 テキストエディター & シンタックス解析（Editor & Syntax）

#### REQ-001: Rope データ構造によるテキストバッファ管理
**説明:**  
The system shall Rope データ構造（`ropey`）を用いてテキストバッファを管理し、100MB 以上のファイルに対しても 16ms 以内のレスポンスでテキスト挿入・削除・行アクセスを実行する。

**受入条件:**
- [ ] 100MB テキストファイルを開いた際の初期ロード時間が 500ms 以下であること。
- [ ] 任意の行・桁へのカーソル移動および編集操作が 60fps (16ms 未満) で描画更新されること。

**優先度:** Must  
**備考:** メモリコピーを最小限に抑えるピース管理を行う。

---

#### REQ-002: Tree-sitter による構文解析とハイライト
**説明:**  
The system shall Tree-sitter の増分構文解析エンジンを統合し、タイピングごとの差分構文解析により 5ms 以内にトークン種別を判定して文字色およびフォントスタイルを更新する。

**受入条件:**
- [ ] Rust, TypeScript, Python, C++, Go, Markdown, JSON, YAML のシンタックスハイライトが動作すること。
- [ ] 編集時に入力箇所周辺のみを再解析し、UI スレッドをブロックしないこと。

**優先度:** Must  

---

#### REQ-003: Language Server Protocol (LSP) 連携
**説明:**  
The system shall JSON-RPC 2.0 経由で LSP サーバーと非同期通信し、ホバー情報・定義ジャンプ・コード補完・リアルタイム診断エラー・セマンティックトークンハイライトを提供する。

**受入条件:**
- [ ] `rust-analyzer`、`typescript-language-server`、`gopls` と通信し、補完候補一覧をポップアップ表示できること。
- [ ] 診断エラー（Diagnostics）を下線波線およびエディター左端のガター（Gutter）にアイコン表示できること。

**優先度:** Must  

---

### 4.2 ディレクトリ可視化（Folder Tree / Explorer）

#### REQ-004: ファイルツリー表示とファイル操作
**説明:**  
The system shall ワークスペースのディレクトリ構造をツリー形式で左側サイドバーに可視化し、ファイルの新規作成・名前変更・削除・移動（ドラッグ＆ドロップ）を実行する。

**受入条件:**
- [ ] 10,000 ファイル以上のプロジェクトで仮想スクロールにより遅延なくツリーを描画できること。
- [ ] OSのファイルシステム変更イベント（notify）を検知し、ツリー表示を自動同期すること。
- [ ] Git の無視ファイル（`.gitignore`）をグレーアウト表示、または非表示に設定できること。

**優先度:** Must  

---

### 4.3 Git GUI 操作（Source Control）

#### REQ-005: Git 変更検出と差分表示（Diff View）
**説明:**  
The system shall リポジトリ内の変更ファイル一覧（Unstaged / Staged / Untracked）を表示し、サイド・バイ・サイドまたはインラインでの差分比較画面（Diff View）を提供する。

**受入条件:**
- [ ] 変更箇所の追加行（緑色）および削除行（赤色）を行番号付きで視覚化できること。
- [ ] ファイル単位およびハンク（Hunk）単位での Stage / Unstage 操作ができること。

**優先度:** Must  

---

#### REQ-006: コミットおよびブランチ操作
**説明:**  
The system shall コミットメッセージ入力によるコミット作成、ブランチの作成・切り替え・マージ、リモートへの Push / Pull 操作を GUI から実行する。

**受入条件:**
- [ ] コミットメッセージを入力して Commit ボタンを押下した際、ローカルコミットが正常に生成されること。
- [ ] 現在のブランチ名をステータスバーに常時表示し、クリックでブランチ切り替えポップアップを表示できること。

**優先度:** Must  

---

### 4.4 統合ターミナル（Integrated Terminal）

#### REQ-007: 仮想端末（PTY）の実行と描画
**説明:**  
The system shall OS ネイティブの PTY（Windows では ConPTY、macOS/Linux では openpty）を介してシェル（PowerShell, bash, zsh 等）をバックグラウンド実行し、下部パネルに ANSI エスケープシーケンス対応のターミナルを描画する。

**受入条件:**
- [ ] キーボード入力を PTY へ送信し、シェルの出力を 60fps でターミナル画面に描画できること。
- [ ] 複数ターミナルタブの作成・切り替え・終了ができること。

**優先度:** Must  

---

### 4.5 拡張機能システム（Plugin & Theming）

#### REQ-008: WASM プラグインホスト
**説明:**  
The system shall WebAssembly ランタイム（Wasmtime または Extism）を内蔵し、サンドボックス化された環境でサードパーティ製プラグイン（コマンド拡張、カスタム言語定義、ステータスバー拡張）を実行する。

**受入条件:**
- [ ] プラグインがエディターのバッファ読み取り・テキスト置換・コマンド登録用 API を呼び出せること。
- [ ] 1つのプラグインがパニックまたはクラッシュしても、メインエディタープロセスが終了せず安全にエラーハンドリングされること。

**優先度:** Must  

---

#### REQ-009: テーマおよびキーバインドのカスタマイズ
**説明:**  
The system shall JSON/TOML 形式の設定ファイルにより、カラーテーマ（ダーク/ライト/VS Code 互換カラー）、フォントファミリ、フォントサイズ、キーバインドマッピングを動的に切り替える。

**受入条件:**
- [ ] 設定ファイルの変更をホットリロードし、エディターの再起動なしに UI テーマが即座に反映されること。

**優先度:** Should  

---

### 4.6 高速検索（Search & Replace）

#### REQ-010: ファイル内検索および置換
**説明:**  
The system shall アクティブなエディターバッファ内において、プレーンテキストおよび正規表現による前方/後方検索・マッチ箇所のハイライト・単一/一括置換を実行する。

**受入条件:**
- [ ] マッチした全箇所の行番号と出現数を検索バーに表示できること。
- [ ] `Ctrl+F` で検索バー、`Ctrl+H` で置換バーが開閉すること。

**優先度:** Must  

---

#### REQ-011: プロジェクト全体検索およびファイル名ファジーファインダー
**説明:**  
The system shall `ripgrep` コアライブラリ（`grep-regex` / `ignore`）を利用してワークスペース全体のテキスト検索を並列実行し、またファイル名のファジーマッチング（`Ctrl+P`）により 10ms 以内に候補一覧を表示する。

**受入条件:**
- [ ] プロジェクト検索結果をファイルごとにグループ化して一覧表示し、クリックで該当行へ即座にジャンプできること。
- [ ] `.gitignore` の除外ルールを遵守して検索対象をフィルタリングできること。

**優先度:** Must  

---

### 4.7 Markdown 即時レンダリング（Markdown Live Preview）

#### REQ-012: Markdown リアルタイムプレビューと同期スクロール
**説明:**  
The system shall CommonMark / GFM 準拠の Markdown パーサー（`pulldown-cmark`）を用いてエディター横のスプリットペインに見出し・太字・リスト・表・コードブロック（シンタックスハイライト付き）・画像を即時描画し、エディターと同期スクロールする。

**受入条件:**
- [ ] エディター側でテキストを入力してから 16ms 以内にプレビュー画面の DOM/描画ツリーが差分更新されること。
- [ ] エディター側のスクロール位置に合わせてプレビュー側が対応する見出し位置へ滑らかに連動スクロールすること。

**優先度:** Must
