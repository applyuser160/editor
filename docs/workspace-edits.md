# 複数ファイル編集

Oxide Editor は Language Server Protocol（LSP）が返す `WorkspaceEdit` を、確認可能な編集計画に変換してから適用します。対象は Rename、編集内容を直接返す Code Action、Quick Fix です。適用前に変更一覧を表示し、利用者が **適用** または **キャンセル** を選択できます。

## 対応する変更

| LSP の編集種別 | エディターでの扱い |
|---|---|
| `changes` | URI ごとのテキスト編集を一つのファイル書込みへ正規化します。編集範囲は重複・範囲外を検証します。 |
| `TextDocumentEdit` | テキスト編集を正規化し、開いているタブの文書バージョンを確認します。 |
| `CreateFile` | ファイルを作成します。既存ファイルの上書きは明示された場合にだけ許可します。 |
| `DeleteFile` | 元の内容を保存してから削除します。 |
| `RenameFile` | 既存ファイルの内容を確認してから名前を変更します。 |

未解決の LSP Code Action、すなわち編集結果を返さないアクションは、意図せずコマンドを実行しないよう無効として表示します。

## 安全性と競合

編集計画はワークスペース境界の内側だけに適用されます。未保存のタブ、読取専用ファイル、既存のリネーム先、プレビュー時点から内容が変化したファイル、同じパスに重複する操作、16 MiB を超える編集内容は、適用前に拒否されます。すべての対象ファイルは変更前にバックアップされます。処理の途中で失敗した場合は、バックアップから復元し、失敗理由を表示します。

## Undo と Redo

確認済みのワークスペース編集は一つの操作単位として履歴に記録されます。編集メニューの **元に戻す** と **やり直し** は、ワークスペース編集の履歴がある間はその単位で操作します。履歴がない場合は通常の Monaco エディター編集に委譲します。

Rename のように複数ファイルへ及ぶ操作でも、ファイル書込みとリネームは同じ確認済み計画として適用されます。これにより、Python または Rust のシンボル参照を複数ファイルで更新する際も、部分適用を避けられます。
