# Oxide Editor のワークスペースモデル

Oxide Editor はローカルフォルダーを作業単位とし、**単一ルートまたは複数ルート**のワークスペースを扱います。複数ルートの場合は、常に一つのアクティブルートを選択し、ファイルツリー、検索・置換、Git 操作、統合ターミナル、言語サーバーの作業ディレクトリはそのアクティブルートを使用します。

## 保存場所と共有範囲

ワークスペースの一覧、アクティブルート、最近使ったフォルダー、信頼状態、`files.exclude`、`search.exclude` は、OS のローカルアプリデータディレクトリにある `oxide-editor/workspaces.json` に保存します。このファイルは利用者のローカル設定であり、ワークスペースや Git リポジトリへ書き込まれません。そのため、フォルダーの信頼状態を他者へ共有することはありません。

| データ | 保存先 | 共有範囲 |
|---|---|---|
| ワークスペースフォルダーとアクティブルート | `oxide-editor/workspaces.json` | ローカル利用者のみ |
| Workspace Trust | `oxide-editor/workspaces.json` | ローカル利用者のみ |
| `files.exclude` と `search.exclude` | `oxide-editor/workspaces.json` | ローカル利用者のみ |
| `.gitignore` | ワークスペースの `.gitignore` | Git で管理する場合は共同利用者と共有 |
| 開いているタブとアクティブタブ | ブラウザの `localStorage` | ローカルのアプリプロファイルのみ |

## Workspace Trust

新しく開いたフォルダーは**未信頼**です。未信頼の間もファイルツリーと検索による閲覧は可能ですが、任意コードの実行につながる操作はバックエンドで拒否されます。

| 操作 | 未信頼ワークスペース | 信頼済みワークスペース |
|---|---|---|
| ファイルツリー、検索、読み取り | 利用可能 | 利用可能 |
| 編集・保存 | 利用可能 | 利用可能 |
| 統合ターミナルと端末コマンド | ブロック | 利用可能 |
| 言語サーバーの起動 | ブロック | 利用可能 |
| 拡張機能ランタイムの起動 | ブロック | 利用可能 |

フォルダーを開いた際に信頼確認を表示します。コマンドパレットの **Workspace: Manage Trust** からは、信頼の付与と取り消しをいつでも行えます。信頼状態の確認は UI のフォルダー名にも表示されます。バックエンドでも状態を検証するため、UI を経由しない呼び出しで実行制限を回避することはできません。

> 信頼はフォルダーの内容を安全と保証するものではありません。信頼すると、ターミナル、言語サーバー、拡張機能などがそのフォルダーのコードまたは設定を処理できるようになります。

## 複数ルート

コマンドパレットから次の操作を利用できます。

| コマンド | 動作 |
|---|---|
| **Workspace: Add Folder** | フォルダーを現在のワークスペースへ追加する。重複する正規化済みパスは追加しない。 |
| **Workspace: Select Folder** | アクティブルートを選択する。ファイルツリー、検索、Git、ターミナル、LSP は選択後のルートを使用する。 |
| **Workspace: Remove Active Folder** | アクティブルートを削除し、残るフォルダーへ切り替える。最後の一つは削除できない。 |
| **File: Open Folder Dialog** | 現在の複数ルート一覧を選択した単一フォルダーで置き換える。 |

アプリケーションの再起動後も、フォルダー一覧とアクティブルートはローカルストアから復元されます。削除済みまたはアクセス不能になったフォルダーは復元時に除外します。

## 除外規則

ファイルツリーは `files.exclude`、検索と置換は `files.exclude` と `search.exclude` の両方を使用します。両方の操作はワークスペース直下の `.gitignore` も参照します。既定で `.git`、`node_modules`、`target`、`dist`、ドットで始まるパス、およびシンボリックリンクを除外します。

パターンは単純な `*` と `?` を使うグロブ形式です。スラッシュを含まないパターンは、任意のパス要素に適用します。`.gitignore` の `!` で始まるパターンは、先行する無視規則を取り消します。

| 設定例 | 効果 |
|---|---|
| `generated` | 任意の階層にある `generated` ディレクトリまたはファイルを除外する。 |
| `*.snapshot` | ファイル名が `.snapshot` で終わる項目を除外する。 |
| `build/cache` | ルート直下の `build/cache` を除外する。 |
| `*.log` と `!keep.log` | ログを除外し、`keep.log` のみ含める。 |

**Workspace: Configure Excludes** では、ファイルツリーと検索・置換用の追加パターンを編集できます。設定はローカルストアへ保存され、次回起動時にも復元されます。

## パス境界

すべてのファイル操作はアクティブルートを基準に解決します。相対パスに `..` を含む指定は拒否します。絶対パスや既存の親ディレクトリは正規化してアクティブルート内か検証するため、ワークスペース外のファイルへ直接アクセスできません。ファイルツリー、検索、置換の再帰処理ではシンボリックリンクを走査しません。
