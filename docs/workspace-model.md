# Oxide Editor のワークスペースモデル

Oxide Editor は、ひとつのローカルフォルダーを作業単位とする単一ルートワークスペースを採用します。ワークスペースを開くと、ファイルツリー、検索・置換、Git操作、統合ターミナル、言語サーバーの作業ディレクトリは同じルートを使用します。

## 選択と復元

利用者はコマンドパレットの **File: Open Folder Dialog** からワークスペースを選択できます。選択したルートはネイティブ側で正規化され、最近使用したワークスペースとしてローカルアプリデータに保存されます。**File: Open Recent Workspace** から有効なフォルダーだけを再び開けます。

エディターの開いているタブとアクティブタブは、ルートパスを含むキーでブラウザのローカルストレージに保存します。そのため、別プロジェクトのセッション状態が混在しません。

## パス境界

すべてのファイル操作は選択済みワークスペースを基準に解決されます。相対パスに `..` を含む指定は拒否します。絶対パスや既存の親ディレクトリは正規化してルート内か検証するため、ワークスペース外のファイルへ直接アクセスできません。ファイルツリー・検索・置換の再帰処理ではシンボリックリンクを走査しません。

`.git`、`node_modules`、`target`、`dist`、およびドットで始まるパスは既定でファイルツリー、検索、置換から除外します。

## `.oxide-workspace` 形式

将来、ワークスペース固有設定を持ち運べるようにするため、単一ルートの `.oxide-workspace` は次のJSON形式を予約します。現時点では設定ファイルの自動読込み・書込みは行わず、後方互換性を保った形式だけを定義します。

```json
{
  "version": 1,
  "folders": [
    {
      "path": "."
    }
  ],
  "settings": {
    "files.exclude": [
      "target",
      "node_modules"
    ]
  }
}
```

`folders` は現在1件だけを許可します。複数ルート、`.gitignore` との完全な統合、設定ファイルのUI編集、フォルダー監視の切替は後続の実装で追加します。
