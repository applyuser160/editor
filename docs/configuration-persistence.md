# 設定ファイルの永続化と資格情報の扱い

Oxide Editor は、設定・キーバインド・プロファイルをアプリケーションのネイティブ設定ディレクトリへ JSON として保存します。ワークスペースに固有の設定だけは、開いているフォルダーの `.oxide/settings.json` に保存します。これらのファイルは原子的な一時ファイル置換で更新されるため、書込みの途中で既存ファイルが破損しないようにします。

## 設定ファイル

| 種別 | 保存場所 | 内容 | 共有範囲 |
|---|---|---|---|
| ユーザー設定 | アプリケーション設定ディレクトリの `settings.json` | テーマ、フォントサイズ、タブ幅、Minimap | 同じ端末の利用者 |
| ワークスペース設定 | `<workspace>/.oxide/settings.json` | ワークスペース固有の上書き値 | ワークスペースを共有する場合は Git の扱いに従う |
| 言語別設定 | アプリケーション設定ディレクトリの `language-settings.json` | 言語 ID ごとの上書き値 | 同じ端末の利用者 |
| キーバインド | アプリケーション設定ディレクトリの `keybindings.json` | コマンドとキーの対応 | 同じ端末の利用者 |
| プロファイル | アプリケーション設定ディレクトリの `profiles.json` | 設定、キーバインド、拡張機能 ID の組合せ | 同じ端末の利用者 |

設定ファイルは起動時、ワークスペース切替時、およびアプリケーションが再びフォーカスされた時点で再読込します。外部で JSON を編集する場合は、有効な JSON とサポート済みの設定キーを保存してから Oxide Editor に戻ってください。不正な JSON はエラーとして扱い、利用者が修正するまで既存のメモリ上の設定を保持します。

## 優先順位

設定値は次の順に重ねます。後ろの範囲が同じキーを持つ場合、前の範囲を上書きします。

| 優先順位 | 範囲 | 例 |
|---:|---|---|
| 1 | 既定値 | `fontSize: 14` |
| 2 | ユーザー設定 | 全ワークスペースで使用するテーマ |
| 3 | ワークスペース設定 | 特定リポジトリだけのタブ幅 |
| 4 | 言語別設定 | Rust ファイルだけの Minimap 設定 |

現在サポートする設定キーは `theme`、`fontSize`、`tabSize`、`minimap` です。未知の設定キーや型・範囲が不正な値は受け入れません。

## localStorage からの移行

以前のバージョンは設定、キーバインド、プロファイルを WebView の `localStorage` に保存していました。ネイティブ設定ストアの初期化時に、既存の値を一度だけ対応する JSON ファイルへ移行します。すでに JSON ファイルに値がある場合はその値を優先し、既存データを上書きしません。移行が成功した後にのみ、移行済みの `localStorage` キーを削除します。

## 秘密情報ポリシー

アクセストークン、パスワード、API キー、秘密鍵などの秘密情報を、設定 JSON、ワークスペース、Git リポジトリ、プロファイルのエクスポート、またはアプリケーションログに保存してはなりません。ネイティブ設定ストアは、秘密情報を示すキーを検出すると JSON への保存を拒否します。

資格情報が必要な将来の Git、拡張機能、リモート接続は、OS の資格情報ストアだけを利用します。実装はプラットフォームごとに Keychain Services、Windows Credential Manager、または Secret Service を使用します。[1]

## 検証

Rust 側では、設定スナップショットの原子的保存と再読込、平文の秘密情報フィールドの拒否、言語 ID・資格情報識別子の検証をユニットテストで確認します。フロントエンドでは、ネイティブ設定の初期化後に同じ設定優先順位を解決し、ワークスペース切替時と再フォーカス時に再読込します。
