# Oxide Editor の拡張機能ランタイム

Oxide Editor は Open VSX から取得した VSIX パッケージを検証してローカルへ保存し、有効な Node.js エントリポイントを持つ拡張機能を専用の Node.js 子プロセスで読み込みます。拡張ホストの状態はアプリケーションのステータス領域に表示されます。

## インストールと検証

| 段階         | 実施する検証                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------- |
| ダウンロード | Open VSX の HTTPS URL、レスポンス状態、50 MiB のダウンロード上限を確認する。                    |
| VSIX解析     | 空アーカイブ、10,000件を超えるエントリ、1 MiBを超えるマニフェストを拒否する。                   |
| 展開         | ZIP Slip につながるパスを拒否し、展開先外へ書き込まない。                                       |
| マニフェスト | `publisher`、`name`、`version` の安全な識別子を検証し、インストール対象のIDと照合する。         |
| 実行         | `main` が相対パスであり、展開済み拡張機能ディレクトリ内のファイルに正規化されることを確認する。 |

VSIX アーカイブ、展開ファイル、インストール一覧は OS のローカルアプリデータディレクトリにある `oxide-editor/extensions` に保存します。拡張機能の有効・無効状態はインストール一覧とともに保持されます。

## 実行と信頼境界

Node.js エントリポイントのある有効拡張機能は、アプリケーションプロセスとは別の Node.js 子プロセスで読み込みます。未信頼ワークスペースでは拡張機能ランタイムを起動できません。これは、フォルダーを開いた時点でプロジェクトのコードや設定が実行されることを避けるためです。

> 拡張機能はコードを実行できます。信頼できる提供元の拡張機能だけをインストールし、未信頼のプロジェクトを開くときは Workspace Trust を付与しないでください。

## 現在のAPI範囲

実行時に提供するコンテキストは最小限です。拡張機能の `activate` 関数と `subscriptions` の配列を読み込み、空実装の `commands.registerCommand` を提供します。VS Code 互換のコマンド寄与、設定寄与、言語クライアント、Webview、デバッグアダプター、ホストと拡張機能間の双方向RPCは、専用の権限・IPC・障害隔離設計を伴う後続実装の対象です。

拡張機能をインストールまたは有効化した後、現在はアプリケーションを再起動して新しいエントリポイントを拡張ホストへ反映します。ランタイムは二重起動を防止し、すでに起動中の場合は既存の子プロセスを再利用します。
