# ADR-0001: Rust言語とGPUレンダリングエンジンの採用

- **ステータス:** Accepted
- **決定者:** Syun
- **決定日:** 2026-08-22

---

## コンテキストと問題提起

VS Code は Electron (Chromium + Node.js) をベースとしており、豊富なエコシステムと高い拡張性を持つ一方で、メモリ消費量が大きく（起動時数百MB〜数GB）、巨大リポジトリや大容量ファイルの編集時にレスポンス低下やカクつきが発生します。  
本プロジェクトでは、VS Code の代替となる「極小メモリフットプリント（アイドル時 50MB 未満）」と「常時 60/120fps の滑らかなレンダリング性能」を両立するアーキテクチャを選定する必要があります。

---

## 検討した選択肢

1. **Rust + WGPU / Vello（ネイティブGPUレンダリング）**
2. **C++ + Qt / Skia**
3. **Go + Gio / Fyne**
4. **Tauri (Rust + WebView)**

---

## 決定結果

**選択肢 1: Rust + WGPU / Vello** を採用します。

### 決定理由

- **ゼロGCと予測可能な低レイテンシ:** Rust はガベージコレクションを持たないため、タイピング中や大容量スクロール時の GC によるフレームドロップが一切発生しません。
- **極小メモリフットプリント:** ネイティブバイナリとしてコンパイルされ、不要なブラウザエンジンを排斥することで 50MB 未満のメモリ消費を実現可能です。
- **クロスプラットフォーム GPU 加速:** WGPU により Vulkan, Metal, DirectX 12 を統一的に扱い、GPU をフル活用したフォント描画・UI レンダリングが可能です。

### 肯定的な結果

- 高度な並行処理（Tokio 非同期 I/O、マルチスレッドパース）をスレッド安全に実装可能。
- メモリ破壊バグ（バッファオーバーフロー等）がコンパイル時に防止される。

### 否定的な結果・トレードオフ

- Webview や Electron に比べて UI コンポーネントを低レイヤーから構築する必要がある（設計コストの増大）。
