# ADR-0003: WASM（WebAssembly）によるサンドボックスプラグイン基盤の採用

- **ステータス:** Deferred（現行実装では未採用）
- **決定者:** Syun
- **決定日:** 2026-08-22
- **見直し日:** 2026-08-27
- **実装状況:** [VSIXの検証・展開・永続化は実装済み](../implementation-status.md)だが、WASM/WASIランタイム、権限モデル、拡張機能API実行は未実装である。

---

## コンテキストと問題提起

VS Code の成功要因の 1 つは強力な拡張機能エコシステムにあります。  
しかし、サードパーティ製拡張機能が原因でエディター全体がクラッシュしたり、悪意あるプラグインによるファイル不正アクセス・暗号通貨マイニング・情報漏洩といったセキュリティリスクが存在します。  
ネイティブに近い実行速度を保ちつつ、完全なメモリサンドボックスと権限分離を実現する拡張機能ランタイムを選定する必要があります。

---

## 検討した選択肢

1. **WASM / WASI (Wasmtime または Extism)**
2. **埋め込み Lua (mlua)**
3. **埋め込み JavaScript (QuickJS / V8 / Deno core)**
4. **ネイティブ共有ライブラリ (Dynamic Linking / .so, .dll)**

---

## 決定結果

**この方針は延期します。** 現行実装は VSIX パッケージの検証・展開・管理に限定され、WASM/WASI ランタイムおよび拡張機能 API 実行は有効化していません。ランタイム、権限モデル、失敗隔離を設計・検証するまで導入しません。

### 決定理由

- **強固なサンドボックス:** WASM はメモリ空間がホストプロセスから完全に分離されており、プラグイン内で不正ポインタ操作やパニックが発生してもエディター本体は影響を受けません。
- **言語非依存の開発性:** 開発者は Rust, TypeScript (AssemblyScript), Go, C/C++ 等、任意の WASM 対応言語で拡張機能を開発できます。
- **きめ細やかな権限管理:** ファイルシステム、ネットワーク、コマンド実行などのアクセス権限をユーザーが個別に許可/拒否する Capabilities ベースのセキュリティモデルを構築可能です。

### 肯定的な結果

- 高度な安全性と、ネイティブに匹敵する実行パフォーマンス（JIT/AOT コンパイル）。
- 多様な言語コミュニティからのプラグイン作成を誘致可能。

### 否定的な結果・トレードオフ

- ホストとゲスト（WASM）間のデータ受け渡し（メモリコピー / シリアライズ）にオーバーヘッドが生じるため、効率的な共有メモリプロトコルの設計が必要。
