# ADR-0004: Tree-sitterとLSPによるハイブリッド構文解析・ハイライトの採用

- **ステータス:** Deferred（現行実装では未採用）
- **決定者:** Syun
- **決定日:** 2026-08-22
- **見直し日:** 2026-08-27
- **実装状況:** [LSPの起動・JSON-RPC基盤は部分実装](../implementation-status.md)だが、Tree-sitter、言語グラマー、セマンティックトークン統合は未実装である。

---

## コンテキストと問題提起

コードエディターにおける文字色やフォントの視覚的フィードバック（シンタックスハイライト）は、タイピング体験の快適性を左右します。  
TextMate 形式の正規表現ハイライトは高速ですが文脈に応じた型・変数判定が困難です。一方、LSP のセマンティックハイライトは高精度ですがネットワーク/IPC 遅延により初期表示やタイピング時に遅れが生じます。  
瞬時の描画レスポンスと高度な型・シンボル認識を両立する構文解析アーキテクチャが必要です。

---

## 検討した選択肢

1. **Tree-sitter（増分構文解析）+ LSP セマンティックトークンのハイブリッド**
2. **TextMate 正規表現グラマーのみ (syntect)**
3. **LSP セマンティックトークンのみ**
4. **自作 PEG / 手書きパーサー**

---

## 決定結果

**この方針は延期します。** 現行実装には Tree-sitter、言語グラマー、LSP セマンティックトークン統合がありません。導入対象言語、グラマー更新方針、性能計測を設計・検証するまで実施しません。

### 決定理由

- **インクリメンタル（増分）解析による即時ハイライト:** Tree-sitter はキーストロークごとに差分ノードのみを再解析するため、数ミリ秒以内で正確な AST 構築と基本ハイライト（キーワード、文字列、コメント、演算子）が完了します。
- **LSP によるセマンティック拡張:** 言語サーバー（rust-analyzer 等）から非同期で型情報やスコープ情報（変数・定数・トレイト・ジェネリクス等の区別）が到着した段階で、ハイライト情報を差分オーバーレイ（洗練）します。
- **フォールバック耐性:** 言語サーバーが起動していない環境や未サポートの言語でも、Tree-sitter のみで高品質なハイライトを提供可能です。

### 肯定的な結果

- キー入力直後のハイライト遅延がゼロ（60fps維持）。
- 型定義やマクロ展開に応じた VS Code 同等の高精度なカラーリングが実現。

### 否定的な結果・トレードオフ

- Tree-sitter の C/Rust バインディング管理および言語グラマーのコンパイル設定が必要。
