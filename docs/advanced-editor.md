# 高度なエディター機能

Oxide Editor は、比較、競合解決、コード探索、大規模ファイル閲覧のために Monaco Editor の機能を拡張します。ここで説明する機能は Rust、Python、TypeScript、JavaScript、Go の LSP 統合が利用可能なワークスペースで段階的に有効になります。

## Git 差分と比較

ソース管理ビューの変更ファイルには **比較** ボタンがあります。比較画面では HEAD の内容とワークツリーの内容を Monaco Diff Editor で開き、**左右比較** と **インライン** を切り替えられます。新規ファイルは空の基準内容と、削除ファイルは空の変更後内容を比較対象にします。バイナリまたは読み出せないファイルは比較しません。

| 状況 | 操作 | 結果 |
|---|---|---|
| 変更済みファイル | SCM の **比較** | HEAD とワークツリーを左右またはインラインで比較します。 |
| 未解決の競合ファイル | SCM の **3-way マージ** | Git index の Base、Ours、Theirs と編集可能な Result を表示します。 |
| 競合解決後 | **解決結果を保存** | 結果をワークツリーへ保存します。内容を確認してから手動でステージします。 |

3-way マージ画面は Ours または Theirs を結果へコピーする補助操作を備え、競合マーカーが残ったまま保存する際には確認を求めます。

## コード探索

定義と参照の LSP プロバイダを使用して、既存の編集位置を保ったまま **Peek Definition** と **Peek References** を表示できます。表示メニューの **アウトライン** は、現在のファイルに対して `textDocument/documentSymbol` を要求し、シンボルを階層付きの一覧として表示します。シンボルを選択すると同じエディターで該当位置へ移動します。

Minimap、コード折りたたみ、sticky scroll はすべてのエディターで有効です。LSP が `textDocument/inlayHint` を実装する場合は、型情報などの Inlay Hint も表示します。サーバーがその要求を未対応としても、エディター操作は継続します。

## 性能基準

10,000 行程度の UTF-8 テキストファイルについて、ファイルを開く、スクロール、検索、アウトライン要求、インライン・左右差分の切替を主要操作とします。基準環境では各操作が継続的な UI フリーズを起こさないことを目標とし、Diff Editor では Minimap を無効にして表示負荷を抑えます。極端に大きいファイルや大量の差分では、LSP の応答時間と使用するアダプタの制約により結果表示が遅延することがあります。
