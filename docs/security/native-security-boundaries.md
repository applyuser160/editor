# Oxide Editor のネイティブ機能における信頼境界

Oxide Editor はローカルファイル、Git、擬似端末、言語サーバー、拡張機能アーカイブを扱うデスクトップIDEです。本書は、Tauriフロントエンド、Rustコマンド、ワークスペース、ネットワーク取得物の間にある信頼境界を定義します。

## Capability の最小権限

メインウィンドウの `default` Capability は `core:default` に加え、ファイルを開く・保存するための `dialog:allow-open` と `dialog:allow-save` だけを許可します。クリップボードと外部URL起動のTauriプラグインは現在の製品コードから利用していないため、依存関係およびCapabilityから除外しています。

| 機能 | 実装経路 | 信頼境界 | 現在の制限 |
|---|---|---|---|
| ファイル選択・保存 | Tauri Dialog | 利用者が選択したローカルパス | `dialog:allow-open` と `dialog:allow-save` に限定 |
| ファイル編集・検索 | Rustコマンド | ワークスペースとファイルシステム | パス操作の改善は継続課題 |
| Git | Rustの `Command` | ローカルGitリポジトリ | ブランチ名を検証し、ファイル引数の前に `--` を付与 |
| 統合ターミナル | PTY | 利用者が明示的に実行するコマンド | 任意コマンド実行であることをUI上で明示する必要がある |
| Open VSX検索 | HTTPS API | `open-vsx.org` | CSPの接続先をOpen VSXに限定 |
| VSIX取得 | HTTPSダウンロード | Open VSXの配下ホスト | HTTPS、ホスト、50 MiB上限を検証。署名検証は未実装 |

## コンテンツセキュリティポリシー

Tauri設定では、既定の読み込み元をアプリ自身に限定しています。ネットワーク接続と拡張機能アイコンの読み込み先は `open-vsx.org` とそのサブドメインに限定し、フォーム送信、プラグイン、フレーム埋込みは無効化します。Monaco EditorのWeb Workerを動作させるため、`worker-src 'self' blob:` を許可しています。

インラインスタイルは既存HTMLの静的なレイアウト指定でのみ利用されているため、`style-src` では暫定的に `'unsafe-inline'` を許可しています。将来は該当スタイルをCSSファイルへ移し、当該許可を削除します。スクリプトについてはインライン実行を許可せず、アプリ同梱のモジュールとWasm評価に限定します。

## 入力検証の基準

Gitブランチ名は、先頭ハイフン、空白、制御文字、参照構文として無効な文字列を拒否します。これにより、ブランチ選択・作成画面からGitコマンドのオプションを注入する経路を防ぎます。ステージ・アンステージ対象のファイルパスには `--` を付け、ハイフンから始まるファイル名がGitオプションとして解釈されないようにします。

VSIXのダウンロードURLはHTTPSであり、ホストが `open-vsx.org` またはそのサブドメインである場合だけ受け入れます。Content-Lengthと実際に読み込んだバイト数の双方に50 MiB上限を適用します。

## 残るリスクと次の対応

この変更はIssue #36の初期的な防御層です。ワークスペース外パス、シンボリックリンク、拡張機能の署名・マニフェスト検証、PTYコマンドの利用者確認、ネットワーク取得物のハッシュ検証、セキュリティ回帰テストの拡充は、後続の実装で対応します。特にVSIXは現時点で実行サンドボックスを提供しないため、信頼できる公開元以外の拡張機能を導入しないことを前提とします。
